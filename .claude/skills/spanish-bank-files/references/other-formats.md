## 1. No national ledger exchange format

- Spain has no statutory or de facto standard file for exchanging a full general ledger between programs, unlike Sweden's SIE or the OECD SAF-T adopted by Portugal, Poland, Norway and others. Spain has not adopted SAF-T for general reporting (unverified as of Nov 2026; no BOE instrument found).
- Real-time VAT data reaches AEAT through the SII (large and monthly-period taxpayers) and, from 2027, Verifactu (everyone else in territorio común), not through a ledger file.
- Inspectors request the books in electronic form during audits (RD 1065/2007; LGT art. 29, 142); spreadsheet or CSV exports are common in practice.

## 2. Formats that do exist

| Format | Owner / basis | Content | Use |

| Norma 43 / camt.053 | AEB-CECA-UNACC / ISO 20022 | Bank statements | Import into accounting (`norma43-format.md`) |
| SEPA pain.001 / pain.008 | EPC / ISO 20022, Cuadernos 34-14, 19-14, 19-44 | Payments and direct debits | Export to bank (`sepa-iso20022.md`) |
| SII XML web services | AEAT, RIVA art. 62.6 and 69 bis | Invoice-level VAT books (issued, received, intra-EU, investment goods) | Monthly-period VAT taxpayers, within 4 days |
| Verifactu XML (RegistroAlta / RegistroAnulacion / RegistroEvento) | AEAT, Orden HAC/1177/2024 annex | Invoice records with hash chain | SIF users from 2027 |
| TicketBAI XML / LROE | Diputaciones Forales | Invoice files; Bizkaia income/expense ledger | Basque taxpayers |
| Facturae XML; UBL / CII / EDIFACT | facturae.gob.es; EN 16931 | Invoices | B2G now; B2B mandate from 6 Oct 2027 / 6 Oct 2028 |
| SPFE UBL copia fiel and status messages | AEAT, Orden HAC/1028/2026 annexes I-II | Invoice copies, payment and rejection status | B2B mandate |
| Modelo files ("diseños de registro") | AEAT, each modelo's ministerial order | Fixed-length text (or XML) layouts to file returns and information returns (e.g. modelos 303, 111, 115, 180, 190, 347, 349, 390) generated by accounting software and uploaded in the AEAT sede | Tax filing |
| Libros registro de IVA / IRPF in AEAT format | AEAT | Standard spreadsheet/CSV layout for VAT and IRPF books, used when AEAT requests the books (unverified current status) | Audits, IRPF autónomos |

| Depósito de cuentas | Registro Mercantil; annual Orden of the Ministry of Justice approving the models | Cuentas anuales in the official models, XBRL (PGC taxonomy) or PDF via the registradores' D2 software (unverified technical detail) | Companies (`spanish-financial-reporting`) |
| Modelo 200 / 220 | AEAT | Corporate tax return with balance sheet and P&L in PGC structure | `spanish-corporate-tax` |

## 3. Migrating between accounting programs

Because there is no common format, a migration is a mapping project:

```
1. Chart of accounts: export both charts; map subaccounts (Spanish programs commonly use
   PGC 3-4 digit accounts extended to 8-12 digits, e.g. 4300xxxx per customer).
2. Opening balances: post an asiento de apertura with the closing balances of the last
   closed year; check it equals the balance sheet filed (Registro Mercantil, modelo 200).
3. Open items: customers (430), suppliers (400/410), effects (431x, 401x) with due dates
   and invoice numbers, so later bank lines can match.
4. Current-year journal (if migrating mid-year): import per month with entry numbers
   preserved in a reference field; the libro diario must stay chronological.
5. VAT books: import issued and received invoices with all VAT fields (base, rate, cuota,
   RE, ISP flag, exempt cause), otherwise modelos 303/390/347/349 cannot be rebuilt.
6. Fixed-asset register with acquisition dates, cost and accumulated depreciation.
7. Verifactu/TicketBAI: the old system's record chain stays with the old system; the new
   system starts its own chain. Keep the old system's records and event log accessible
   for the limitation period (RD 1007/2023 art. 8.2.c).
8. Validate: trial balance per month equals the source; VAT totals per period equal the
   filed modelos.
```

Common sources and targets: CSV/Excel exports from the programs themselves, proprietary import layouts (e.g. ASCII diario formats of established Spanish packages), and API connectors. Describe what the target accepts; do not invent a "standard".

## 4. What to tell a user who asks for "the Spanish export file"

- For **bank** data: Norma 43 (or camt.053) in, SEPA XML out.
- For **tax authority** data: SII or Verifactu XML (depending on the taxpayer), modelo files, and the books on request.
- For **another accountant or program**: a trial balance, the libro diario and the VAT books as CSV/Excel, plus open items; agree columns with the recipient.
- For **auditors**: the libro diario, mayor, balance de sumas y saldos and the VAT books, usually as spreadsheets; ask for their requested layout.
